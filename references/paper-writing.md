# 建模论文写作与页面编排

## 结构、语言与模板

从题面、正式提交规范、用户模板和本轮要求确认论文结构、语言、页数预算与排版权限。以下中文七章结构供未指定结构时使用。正文标题、图表标题、坐标轴、图例、表内文字与伪代码说明统一使用约定的论文语言，符号和单位沿用领域惯例。目录需要放大时，先确认赛事允许修改，再在目录页局部调整字号，编译核对条目换行、页码和目录所占页数。

## 从结果写正文

每问形成完整论证链：题目要求 -> 状态/变量 -> 控制方程或优化目标 -> 初边值/约束 -> 离散或估计方法 -> 实际求解配置 -> 结果 -> 可由结果支持的机制解释。先完成计算和核对，再补齐摘要与结论。

公式密度由数学工作决定。定义符号、单位、空间与算子；给出弱形式、变换、离散、梯度、正则化、概率模型、误差估计等确实使用的数学对象。公式之后解释它如何进入求解或支持结论。避免连续堆放与主线无关的公式。

用简短的伪代码呈现关键求解流程，写清输入、初始化、更新公式、必要的循环和条件、停止准则及输出。仅给确有阅读价值的求解实例配伪代码，完整实现随复现材料交付。总览流程图优先呈现问题、输入输出与模块关系。用户要求流程图去公式时，将公式保留在相关推导和算法块中。

正文以“建立……”“采用……求解”“计算得到……”“对照表明……”等具体动作组织。去掉“本模型非常先进”“评委可能质疑”“尽管采用高阶工具但不能声称……”一类修辞。必要的适用条件写在模型假设和方程旁，误差来源体现在对照、区间名称和图注中。

## 默认七章

1. 简介：背景和题目重述；不单设文献综述。
2. 问题分析：共同输入与各问计算思路。
3. 模型假设：每条有用途，假设进入相应方程。
4. 名词解释及主要符号说明：物理/统计含义、统一单位。
5. 模型建立与求解：按题目逐问完成推导、计算与结果。
6. 灵敏度分析与鲁棒性检验：真实重算、同条件比较和结论。
7. 模型的评价、改进与推广：优点、具体误差来源、可操作改进与适用推广。

## 摘要的内容分配

摘要包含总述、各问、总结和关键词。总述用一段交代问题对象、主要困难和统一模型。每问用一段说明“针对什么问题，建立什么模型，采用什么求解方法，得到哪些关键数值，说明什么”。最后两三句归纳共同规律及用途。数值从 `numeric_facts.json` 与结果数组交叉核对，保留合理精度和必要配置。

重要模型、关键结果和结论用 `\textbf{}`，不使用红色。题目若要求多个阶段，每段结论应回答相应阶段，不能只罗列方法名和数字。

## 第一页充实且不溢出

1. 采用一页摘要时，沿用模板的标题、段距、字体与版心。根据模板或已确认示例设置首段缩进。用户要求纯文字摘要时，保持整页为文字。
2. 初稿编译，查看摘要和关键词所在页。提取文字只能辅助判断，最终需看渲染页面。
3. 空白较多时优先补充逐问数值、同条件对照、误差验证和具体结论；这些内容必须已有计算来源。
4. 溢出时删去重复背景、重复方法说明或次要参数；保留各问的核心数值和结论。不要用夸张内容填充。
5. 目标为第一页版心充实并保留自然底部空间，关键词留在第一页。目录起始页按模板与提交规范安排，优先用内容取舍匹配版心。

## 正文页面与 PDF 批注

- 用户指定图与特定段落同页、位于页底或相邻时，先为这组内容预留空间。对放在引言底部的总览图，优先调整背景、逐问重述与图高，在不影响可读性的范围内保持引言、引出句、总览图和图注同页。针对用户给出的小幅增删要求，检查改动前后是否发生分页。渲染后核对实际浮动位置，将介绍句和对应图表放在一起，检查是否有单独一句被夹在两个浮动体之间。
- 将图表密度要求应用于有分析内容的正文页。用户允许按两页安排时，尽量让每两个连续正文页至少有一幅能支持当前论证的图。重要图优先使用接近版心全宽的尺寸，逐页核对图内最小文字。在图文同页且空间有限时可适当缩小流程图，以最终 PDF 中的文字和箭头清楚可辨为准。重复实验图可转入附录。摘要和参考文献页保持各自的功能。
- 定位批注时用选中文字、图表标签和实际内容交叉确认。页码或编号重排后按语义定位，应用已确认的修订并复查同类位置。讨论页留白较大时，可补充结果解释、适用边界及能落实的改进措施。 [图件调整与渲染检查](figure-design.md)

## 数值、引用与命名

结果表采用题设四舍五入，内部计算保留原精度。不同网格、样本量和参数设置有独立名称；相同物性对照才能量化几何效应。后验可信区间、设计输入的预测分位数、数值误差带各自准确命名。

优先选用与当前论点直接相关、已核验的近期领域研究，引用放在所支持的机制、方法或结论旁。编号按模板或赛事规范设置。正式年份取已核验的卷期或出版日期。最低文献数量和题面是否计入参考文献按项目要求执行。需要交代题面来源时，在正文或来源记录中说明。

## 修订与源文件

已有最终稿时先阅读活动 `main.tex` 的递归输入。修改模块化源并重新生成所需单文件；如果用户直接编辑单文件，则先保存差异并合并。不要运行从旧快照重建整稿的历史程序。

单独生成表格和数字宏，单独绘制最终图件。生成器必须声明输出文件，避免一个旧脚本同时重建正文、旧配色图和过期摘要。待图表定稿后从活动源重新编译，按交付规范核对 PDF、源文件、工作簿和复现包。 [交付检查](delivery.md)

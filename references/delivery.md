# 构建、验收与提交

## 三种成果

- 论文：最终PDF、活动LaTeX源、参考文献和最终图件。
- 题目规定的结果：按题设命名、布局、采样和精度生成Excel/CSV等文件。
- 复现工程：代码、输入副本、未舍入数据、配置、数值与统计诊断、引用证据及运行说明。

核心提交包只包含题目和正式提交通知要求的文件。源码支撑包供复现或按组委会入口提交。将上传栏目、所需文件、命名、扩展名和大小上限与当前正式通知逐项对应。分别标明最终论文、比赛支撑材料和内部复现包供何处使用。

## 明确交付契约

在 `project.json` 的 `required_deliverables` 中写相对路径，例如：

```json
{"required_deliverables":["delivery/paper.pdf","results/result1.xlsx","results/result2.xlsx"]}
```

路径指向已生成的最终文件。按题目实际要求决定是否另交工作簿、签字文件或 AI 声明。若规则规定 AI 声明为独立文件，按指定文件名和格式交付。按规则填写实际工具、可确认的版本、提供方、日期、用途、真实交互摘要及人工修改。

## 编译与检查

```bash
python scripts/build_paper.py --project PROJECT --main main.tex
python scripts/audit_project.py --project PROJECT
python scripts/package_submission.py --project PROJECT
```

这些路径相对技能目录。`build_paper.py` 在项目目录运行LaTeX，默认禁用shell escape；按本轮辅助文件自动运行BibTeX或Biber，手写参考文献列表则直接编译。构建在 `notes/build/` 下使用临时目录，完成后写入 `manuscript.output_pdf` 指定的 PDF，默认 `delivery/paper.pdf`。若使用正式命名，将相同路径写入 `required_deliverables`。审计默认读取同一路径。

查看构建日志中的未定义引用、缺字和超出边界。无报错只证明编译通过；渲染摘要、目录、改变过的页面、所有图表和文献页，核查裁切、重叠、图注、单位和分页。审计脚本提供可机械检查的证据，科学结论仍须结合计算和数据审阅。

## 打包行为

打包脚本读取明确的 `required_deliverables`，在核心包中使用各文件原始文件名；重名会报错。复现包收入项目内约定目录和源文件，不收集隐藏凭据、虚拟环境、依赖目录、旧构建缓存或已有压缩包。所有文件有 SHA-256 清单。读取中发生变更时重新核对源文件和打包时间。比赛支撑材料按栏目要求选取代码、结果、可编辑图源和运行说明。赛题数据是否随包及匿名范围由当届规则决定。上传版检查压缩包、内嵌图源和 PDF 属性中的身份信息。

用户指定模板需要进入私有复现工程时可保留其原始文件和许可证。开源发布前单独检查题目、数据、模板、字体、第三方代码的再分发许可；本技能公开发行包使用独立原创模板和解析演示。

## 校验修订后的工程

局部修订回到活动源文件，随后编译论文并复核受影响页。逐个确认最终 ZIP 内的活动入口、图件和关键结果与源文件来自同一版本。保留当前论文 PDF、源文件、模板、数据和可编辑图。获得清理授权后，将已确认没有依赖的旧稿、临时预览、重复交付件和废弃导出从项目移出。根目录的 `main.tex` 通常是可编辑入口，手动编译时出现的 `main.pdf` 常是本地预览。用路径、引用和哈希区分版本。

仅供本地保存的材料沿用用户指定的名称和位置。复现包会自动收集约定目录内的文件。将只留本地的材料放在收集范围之外，或从已核对的独立目录生成上传包。若正文引用了本地专用资源，先确认发布版可使用的图件或替代内容，再编译发布版。核对每个压缩包的实际清单。

公开技能仓库仅纳入通用规则、工具和可公开的演示材料。用户的原始对话、批注截图、题面、结果、内部复现包和身份信息留在私有工作区。

## 本地编辑与在线工具

本机已经有TeXstudio时沿用其XeLaTeX配置，给出真实文件路径。用户明确要求在线协作时才操作Overleaf并确认保存完成，不能仅凭网页打开声称已同步。遇到编辑器不可用先完成本地源和PDF，不让UI状态阻断可执行计算。

最终响应列出实际完成的核心文件与复现包，简述采用的模型、计算检验和剩余依赖。未运行的模型、未取得的数据或未完成的外部上传直接说明，不用成功措辞代替验证。

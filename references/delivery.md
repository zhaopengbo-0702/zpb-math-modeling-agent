# 构建、验收与提交

## 三种成果

- 论文：最终PDF、活动LaTeX源、参考文献和最终图件。
- 题目规定的结果：按题设命名、布局、采样和精度生成Excel/CSV等文件。
- 复现工程：代码、输入副本、未舍入数据、配置、数值与统计诊断、引用证据及运行说明。

核心提交包只包含题目和正式提交通知要求的文件。源码支撑包供复现或按组委会入口提交。完整工程是工作归档，不自动视为组委会唯一接收格式。

## 明确交付契约

在 `project.json` 的 `required_deliverables` 中写相对路径，例如：

```json
{"required_deliverables":["delivery/paper.pdf","results/result1.xlsx","results/result2.xlsx"]}
```

路径指向已生成的最终文件。题目没有规定额外文件时不强行套用历史药材案例的四个工作簿。正式通知未提供时，在交付说明中标明尚待按通知确认的命名、身份页及AI声明格式，不臆造规定。

## 编译与检查

```bash
python scripts/build_paper.py --project PROJECT --main main.tex
python scripts/audit_project.py --project PROJECT
python scripts/package_submission.py --project PROJECT
```

这些路径相对技能目录。`build_paper.py` 在项目目录运行LaTeX，默认禁用shell escape；按本轮辅助文件自动运行BibTeX或Biber，手写参考文献列表则直接编译。成功后复制PDF到 `delivery/paper.pdf`。它不会自动安装系统软件或改写模板。

查看构建日志中的未定义引用、缺字和超出边界。无报错只证明编译通过；渲染摘要、目录、改变过的页面、所有图表和文献页，核查裁切、重叠、图注、单位和分页。审计脚本提供可机械检查的证据，科学结论仍须结合计算和数据审阅。

## 打包行为

打包脚本读取明确的 `required_deliverables`，在核心包中使用各文件原始文件名；重名会报错。复现包收入项目内约定目录和源文件，不收集隐藏凭据、虚拟环境、依赖目录、旧构建缓存或已有压缩包。所有文件有SHA256清单；任何文件在读取过程中变化将使本次打包失败，避免混合版本。

用户指定模板需要进入私有复现工程时可保留其原始文件和许可证。开源发布前单独检查题目、数据、模板、字体、第三方代码的再分发许可；本技能公开发行包使用独立原创模板和解析演示。

## 本地编辑与在线工具

本机已经有TeXstudio时沿用其XeLaTeX配置，给出真实文件路径。用户明确要求在线协作时才操作Overleaf并确认保存完成，不能仅凭网页打开声称已同步。遇到编辑器不可用先完成本地源和PDF，不让UI状态阻断可执行计算。

最终响应列出实际完成的核心文件与复现包，简述采用的模型、计算检验和剩余依赖。未运行的模型、未取得的数据或未完成的外部上传直接说明，不用成功措辞代替验证。
